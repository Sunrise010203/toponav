# 直行下一步：既有有效计时的逐帧归因

日期：2026-11-04，Asia/Shanghai。

**本次只完成后验描述统计，没有运行新性能实验、导航、回放或物理闭环，没有改生产代码。**
仅使用上一轮 `benchmark-corrected/` 的完整三例、每版四轮有效计时；无效首批不混入。
原始补丁/NCC 候选仍被拒绝，默认保留此前已接受的总体去重。

## 结论

1. **正横偏退化不能简单归为一两张慢帧。** 三轮总耗时退化分别有
   53/80、63/80、48/80 个相同 tick 的候选调用更慢；汇总的最慢五个正差值只占
   全部正差值的 13.32%，前十个占 21.69%。
2. **也不能证明是普遍、稳定的固定开销。** 四轮中第一轮改善 11.532s，后面
   三轮分别退化 3.051/9.007/1.590s；72/80 个 tick 在四轮出现过正负翻转。
   只有 8 个 tick 四轮均变慢，其中两个只是亚毫秒级启动调用。
3. CPU 与墙钟差值同向、强相关，但**没有主机运行队列、频率或逐线程信息，不能
   据此判定缓存算法、BLAS、调度、温度或“噪声”是根因**。也不能删掉第一轮或
   重跑到有利为止。
4. 原性能门槛仍失败：正横偏完整序列墙钟中位退化 **4.884%**，均值退化
   **1.011%**。本分析不新增验收规则、不推翻拒绝结论。

## 正横偏：慢帧分散与跨轮重复性

320 个计时帧对中 178 个更慢、142 个更快。全部正差值合计 **23.763140s**，
全部负差值合计 **-21.648172s**，抵消后的净差仅 **+2.114969s**。
因此“单帧占净差多少”极易失真：以下分母始终是**全部正差值**，不是抵消后的净差。

| 描述统计 | 值 |
|---|---:|
| 最大一个正差值 / 全部正差值 | 3.63% |
| 最大五个正差值 / 全部正差值 | 13.32% |
| 最大十个正差值 / 全部正差值 | 21.69% |
| 累积达到 50% 正差值所需帧对 | 35 |
| 累积达到 80% 正差值所需帧对 | 78 |

逐轮（1/2/3）最大的五个正差值占该轮全部正差值 38.55%/24.73%/29.72%；
不能说退化完全由极少数尾部调用构成。这里没有删除任何帧或用截尾统计替换门槛。

按 tick 统计四轮变慢次数：0次=0个，1次=16个，2次=38个，3次=18个，4次=8个。
**72/80 个出现过正负翻转，其中 38 个是两轮变慢、两轮变快。**

四轮均变慢的 tick 为 3、7、49、52、53、56、62、70：

- 3、7：原均值分别约 .591/.442ms，候选约 .903/.896ms；绝对差很小，
  不据此声称重计算路径稳定退化。
- 49/52/53/56/62/70：平均配对 wall 差约 +198/+266/+97/+173/+138/+68ms。
  tick 56 的输出状态是 `waiting_evidence`，其余五个是 `following`。
  跨轮同向只提供进一步检查的线索，不证明具体函数因果。

四个连续 tick 区段（0–19/20–39/40–59/60–79）的净差(s)：
