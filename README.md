# TopoNav：先验拓扑图引导的跨场景视觉导航

TopoNav 研究如何让小车利用**先验拓扑连接、相机看到的道路结构、行驶历史和执行反馈**进行定位与导航，而不是依靠记忆每个地点的照片或直接读取仿真坐标。

项目已具备拓扑规划、四向 RGB 结构感知、离散与时序导航、受限连续控制，以及 PyBullet / Gazebo / ROS2 工程接入。**当前仍是研究与受限仿真原型：普通直行 S2 未通过，统一安全验收 S6 未完成，连续链路尚未达到 10Hz。**

## 1. 原始目标与研究范围

对照仓库保存的[初期设计](docs/specs/2026-10-12-toponav-design.md)和[七分块整体规划](docs/PROJECT_HANDOFF_2026-10-15.md)，主线目标是：

> 提前提供地图中的节点连接与出口关系，不为测试地图逐点采集参考照片；使用通用道路结构感知与拓扑推理，在未参与训练的模拟布局中完成导航，并解释何时不确定、如何停止或恢复。

主要约束如下：

- **识别道路结构，不识别节点编号**：同一种路口可出现在多个地点，看到 T 形路口不等于知道具体节点，目标节点也不是一个视觉类别。
- **地图不必包含逐点照片或精确坐标**：连接关系、出口方向与任务信息服务于定位和规划；几何信息另用于渲染、显示及评价。
- **第一版已知任务起点、目标和初始朝向**：不是未知起点的全局定位，也不是未知环境建图；当前覆盖室内正交通道和双向简单图。
- **保留前、左、右、后四向 RGB 基线**：不默默加入深度、激光、里程计或额外相机来证明原方法有效；使用辅助信息时必须单独声明。
- **控制与真值审计单向隔离**：真实位置、接触、到达判据可用于事后评价，但不能回流修正定位与控制决策。
- **先完成仿真方法验证，再考虑部署扩展**：完整 SLAM、未知环境主动探索、强化学习、多车协同不在当前主线；量化、端侧和实车验证属于后置扩展。

## 2. 系统功能与架构

### 2.1 拓扑地图、定位与规划

- 统一 v2 地图与场景格式，支持不同节点数量、任意节点编号、出口绑定、任务配置与非法输入校验。
- 通过候选节点/朝向集合融合结构观测与执行历史；对歧义、结构冲突、未知朝向或未确认执行保持停止。
- 由公共 Dijkstra / 路径规划接口计算路线、处理禁行与不可达，再根据已确认朝向转换为相对动作，避免各入口各写一套规划器。
- 保留无几何、无照片的离散导航能力；旧 v1 节点概率导航仅作为历史对照，不作为当前通用视觉主路线。

默认六节点示例任务为 N01 → N06，路线 N01 → N02 → N03 → N04 → N06；关闭 C02 后可经 N05 绕行，关闭 C06 则目标不可达。换节点编号或数量不需要把视觉类别改成该地图的节点标签。

### 2.2 四向视觉感知

- 实际输入为四向同步 RGB，每方向 128×128，拼成 256×256 面板；前、左、右、后具有固定顺序。
- 使用共享、冻结的 MobileNetV3-Small 骨干提取四向特征，训练分类头，输出 **16 种相对出口组合 + `unobservable`**，不预测地图节点 ID。
- 已有按布局隔离的模拟数据、冻结模型、预处理、训练/评估与图像驱动离散导航入口。
- 遮挡、过渡阶段及相关错误下的拒识仍不足；高结构分类准确率不等于可靠安全感知，多帧一致也不保证正确。

### 2.3 时序会话与有限恢复

- 在停车后持续接收新鲜观测，以多帧确认替代单帧立即行动；重复旧帧不会重复计票。
- 用命令与反馈事件绑定、去重和超时，防止同一执行反馈被应用多次、连续看见同一路口被误算成跨越多个节点。
- 支持有界的停车重观察与被动恢复；不可辨或超时则终止，不盲目掉头、探索或读取真值重置候选。
- 原子执行入口与连续控制语义分开：部分平移、半转弯不能套用“失败即原地未动”的离散假设。

主线调用关系：

```text
四向 RGB → 结构预测与有效性检查 → 时序确认 / 候选定位
                                      ↓
任务与先验拓扑 → 公共路径规划 → 相对动作 → 执行器 / 连续控制
                                      ↑             ↓
                               命令绑定的执行反馈 + 新图像

物理位姿 / 接触 / 几何到达判据 → 事后审计与显示（不回流决策）
```

### 2.4 连续运动、仿真与工程演示

已有真实仿真轮驱、RGB 纠偏、转角和路口控制、停车、公共输入回放，以及相机故障、反馈异常和租约超时等保护机制。不同入口的先验与能力不能混为一谈：

| 入口 / 模式 | 已有功能 | 与原目标的关系及限制 |
| --- | --- | --- |
| 理想结构 / 图像驱动离散导航 | 公共拓扑规划、结构候选定位、原子动作执行 | 可不依赖逐点照片；原子通道遍历不是连续驾驶 |
| PyBullet 连续 L / T 与多节点路线 | 真实轮驱、RGB 闭环转弯、分支选择、阻挡等待、节点确认 | 已有受限场景验证；部分多节点路线依赖带标签参考 RGB，不能当作无逐点照片目标全部完成 |
| Gazebo `vision` | 冻结 17 类模型 → 结构定位/规划 → RGB 几何控制 → 下一节点确认 | 无人工路标开发模式；已有固定场景闭环演示，但依赖显式标定、地面/墙体与场景假设，不是未见布局泛化或 S2/S6 验收 |
| Gazebo `route` | 六节点行驶、转弯、节点确认、封路绕行及目标停车 | ArUco / 黄线辅助独立工程基线，使用额外相机；不属于原无标记视觉方法的完成证明 |
| Gazebo `topology` | 原地图、任务规划、物理场景及封路预览 | 保持零速，不自动驾驶全图 |
| ROS2 / PyBullet 联调 | 图像、导航、轮控、反馈分进程通信及独立轮控租约 | 已有受限仿真联调，不是 Gazebo 与 ROS2 桥接、完整任务链路或实车验收 |

执行保护包括输入/时钟异常拒绝、终态锁存、执行反馈绑定、租约联锁、零速请求和日志完整性检查。**安全停止不等于导航完成，未观察到碰撞不等于全面无碰撞认证。**

PyBullet 浏览器面板支持审计轨迹、四向 RGB、控制状态、暂停、倍速和时间轴回放；Gazebo 场景中心提供原生物理窗口、拓扑规划、相机视角、任务/封路选择及运行重置。观察界面的位姿和俯视图不作为驾驶输入。

## 3. 对照原七分块规划：现在做到哪里

本表汇总功能与阶段结论，不把历史通过数当作当前回归结果；部分历史原始工件在当前仓库中缺失，复现状态另见[当前状态记录](docs/REPOSITORY_STATUS_2026-11-13.md)。

| 原规划分块 | 目前已做到 | 尚未完成 / 不能扩大解释的部分 |
| --- | --- | --- |
| 1. 拓扑地图 | v2 地图、任务/结构分离、出口绑定、不同编号与规模、合法性校验 | 按现有正交双向简单图范围维护，不等于任意道路建图 |
| 2. 路径规划 | Dijkstra、禁行处理、不可达判断、可靠估计到相对动作转换 | 恢复或地图变化后仍须满足定位/反馈条件，规划出路线不代表能连续执行 |
| 3. 结构观测闭环 | 候选定位、公开反馈、歧义停止、图像驱动离散接入与真值隔离 | 原子离散模型不覆盖部分移动与全部连续运动情况 |
| 4. 通用视觉感知 | 四向 17 类冻结模型、数据划分、独立评估与结构接口 | 遮挡/过渡拒识和跨外观泛化仍不足，不能称通用安全视觉已完成 |
| 5. 时序融合与鲁棒恢复 | 持续观测、多帧确认、事件去重、超时、有界被动恢复及真实 Predictor 接入 | 不是主动探索、全局重定位或对所有相关误识别的可靠恢复 |
| 6. 模拟器与连续闭环 | 受限视觉几何、L 转角、T 路口、多节点、ROS2 联调及 Gazebo 演示 | **整体未完成：S2 未通过、S6 未完成**；参考照片/标记辅助路线不能替代原目标 |
| 7. 系统对照实验与成果 | 已有感知 P、无逐点照片原子导航 N 的对照/消融、统计与阶段报告 | 连续/ROS 实验轨未执行，部分原始材料缺失；**第七块整体未完成** |

第六块细分中，S1 视觉证据、S3 单转角、S4 T 路口、S5 多节点和 S7 ROS2 有各自受限范围的历史验证；它们不补签 S2/S6，也不自动证明原主线跨布局连续导航已经完成。具体条件见[第六块阶段规划](docs/plans/2026-10-15-block6-goal.md)。

## 4. 还需要做到什么

1. **补足原主线闭环**：在声明的未见模拟布局中，把结构识别、时序定位、公共规划、连续执行和独立节点确认连接起来；显式区分无逐点照片主线与参考图/人工标记辅助基线，不能用后者替代前者。
2. **完成普通直行 S2 与安全 S6**：提高正常走廊、横向偏移和组合偏差条件下的完成率，处理重复纹理启动、近场扫掠自由空间与制动证据；按冻结协议完成相机/通信故障、部分执行、停稳和恢复的独立安全评估，不降低门槛或只统计最终停车。
3. **补足感知与恢复边界**：针对遮挡、过渡、材质/光照、标定变化和对称路段，改进观测有效性与歧义处理；同时报告覆盖率、错误接受、误到达和恢复失败，不以全拒绝冒充改善。
4. **提升连续链路实时性**：在保持证据与数值正确性的前提下优化匹配和控制开销，重新验证完整链路；目前 **10Hz 未达到**，局部加速或旧回放一致不等于实时驾驶能力通过。
5. **完成第七块与可复现交付**：恢复缺失真实归档、处理历史测试导入冲突；满足运行资格并获得授权后，冻结连续/ROS 公平对照与消融任务，保留失败和统计分母，交付可重算结果及完整回归。已有 P/N 阶段成果不代替这部分。
6. **最后再推进部署扩展**：仿真主线稳定后，再确认四向 RGB 的真实硬件方案、完整 ROS2 集成、量化/端侧运行和驱动器超时制动，并开展实车测试；这些是后置工作，不能反过来替代当前仿真方法验收。

## 5. 运行入口

环境基线为 **Ubuntu 22.04 / Python 3.10**，可选 ROS2 Humble。以下假设依赖已经就绪，均在项目根目录执行；新环境依赖说明见[项目总览](docs/PROJECT_OVERVIEW.md)。虚拟环境、私有 Gazebo 运行时和 ROS 构建产物不随 Git 上传。

### 拓扑、规划与离散 / 时序导航

```bash
# 地图与场景校验、默认路线、结构离散导航
.venv/bin/python -m simulation.topology
.venv/bin/python -m simulation.dijkstra
.venv/bin/python -m simulation.structural_navigation

# C02 封路后重规划；C06 关闭后目标不可达，预期退出 1
.venv/bin/python -m simulation.structural_navigation --disable C02
.venv/bin/python -m simulation.structural_navigation --disable C06

# 持续观测、多帧确认与有限恢复
.venv/bin/python -m simulation.temporal_navigation

# 保存新的离散运行记录与轨迹图（绘图需完整节点坐标）
RUN="reports/readme-navigation-$(date +%Y%m%d-%H%M%S)"
.venv/bin/python -m simulation.structural_navigation \
  --output "$RUN/route.json" --plot "$RUN/route.png"
```

合法地图上的目标不可达不等于地图格式错误：导航拒绝运动并退出 1，非法输入退出 2；`simulation.topology` 对合法配置仍退出 0，任务可达性另行报告。

缺失任务/几何/照片的地图也可使用，但必须显式提供任务及朝向，不默认朝东：

```bash
.venv/bin/python -m simulation.structural_navigation \
  --map configs/v2/examples/no_task_no_geometry_no_photos.graph.json \
  --scene configs/v2/examples/no_task_no_geometry_no_photos.scene.json \
  --start N01 --goal N06 --heading 0
```

## 6. 地图、方向、反馈与安全约定

- 默认地图为 `configs/graph.json` / `scene.json`，与 `configs/v2/` 对应；`configs/legacy/` 保留 v1 对照，非法样例必须按 manifest 配对使用。
- `graph.task` 保存起点、目标与初始朝向；`node_type` 只表示结构，`graph.nodes[].exits` 显式绑定邻居、通道与出口方向。
- 地图方向为东 0°、北 90°、西 180°、南 270°。相对动作由朝向与出口关系计算，不能用显示坐标差替代。
- 观测方向是 `front / left / right / back`；统一动作是 `straight / left / right / uturn / stop`，两者不是同一种载荷。离散掉头能力不等于实车掉头安全授权。
- v2 规划代价为 `hops`，规划输出 `length_m=null`；可选几何单独用于米制审计，缺几何时不虚构距离或坐标。v1 保留原米制加权语义。
- 物理开口与通行权限分层：封路不一定改变相机可见道路结构，但公共规划与执行必须拒绝禁行边。
- 结构观测保留 `relative_open` 与 `confidence` 契约；帧、命令和事件元数据由外层包传递。发送命令不是执行成功，终止锁存、零速请求和实际新鲜停稳证据不能互相冒充。

详细接口：[地图 v2](docs/topology-v2-usage.md) · [公共规划](docs/PATH_PLANNING.md) · [Dijkstra](docs/DIJKSTRA.md) · [结构导航](docs/NAVIGATION.md)。
