# 6B-1：RGB 单走廊连续运动原型

这是第六块的第一个独立运动实验，不是完整连续拓扑导航。原有离散执行器与第五块时序入口均保留。

## 运行

在 `/home/sunrise/toponav_project` 中执行，输出目录必须尚不存在：

```bash
export PYTHONDONTWRITEBYTECODE=1
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2
/home/sunrise/toponav_project/.venv/bin/python -m simulation.corridor_motion \
  --output /home/sunrise/toponav_project/reports/my-new-corridor-run \
  --offset 0.2 --yaw 10
```

`--offset` 单位米，正值为走廊中心线左侧；`--yaw` 单位度，正值逆时针。

其他参数：

- `--obstacle none|narrow|full_width`：无障碍、中央窄障碍、整宽中途阻挡。
- `--fault missing_frame|missing_view|occluded|stale_frame|future_frame|replay_frame`：一次性故障，默认第15个控制周期注入。
- `--fault-cycle 0`：在第一次发令前注入。
- `--max-duration 1`：将运动时限设为1模拟秒，验证超时制动。

退出码：0仅表示**独立真值审计确认在端墙前安全停车**；1表示故障、有界退出或未通过端墙位置审计；2表示非法参数/输出目录等错误。整宽中途阻挡即使视觉停车也返回1，不能把所有非零码都当成程序崩溃。

## 实现链路

```text
轮关节电机 → 重力/接触/120Hz物理步进 → 新位置渲染四向RGB
                                              ↓
严格帧身份/模拟时间校验 → 前视RGB地面边界几何估计 → 10Hz v、ω
                                              ↓
                          差速轮目标角速度 → 下一物理周期
```

- 场景与刚体在 `/home/sunrise/toponav_project/simulation/corridor_motion.py`。默认6m×1.8m走廊，车体、两个半径0.08m的驱动轮和两个低摩擦球形支撑；用轮关节速度电机施力。轮距0.30m，默认最高前进速度0.35m/s。
- 相机挂载在车体前方0.20m、车体上方0.29m，静止世界高度约0.45m。沿用前/左/右/后四向、每视图128×128、90°视场，拼成256×256 RGB。
- 控制器在 `/home/sunrise/toponav_project/roadvision/corridor_control.py`，只接收 `frame_id / captured_sim_s / rgb`；不导入PyBullet，不接收真值、深度、分割ID、接触或里程计。
- **米制纠偏使用前视图**；其他视图检查是否缺失，并参与全图停车稳定性检查。不是四向深度融合，也没有调用17类结构分类器。

### RGB 几何与控制

这是明确受限的经典视觉控制器，不是新训练的模型：假设固定蓝灰地面、灰墙、平地、近水平且已标定相机。

1. 从RGB颜色差提取地面；用前视图中央五列的地面起始行，按已知相机高度与焦距估计前方平面距离。
2. 拟合未被图像左右边缘裁切的地面区间中心线。使用中位斜率及至少65%行的一致性检查，排除端墙遮住最上行地面造成的异常点；至少保留6行，不可靠则停止。
3. 从中心线截距与斜率估计朝向误差和横向偏差，比例控制 `ω = -2×朝向误差 -1.3×横向误差`，并限制角速度；接近前方阻挡时降低前进速度。
4. 估计距离≤1.3m时请求零轮速；必须再有3张新鲜、唯一且变化较小的图像才记为 `visual_stop`。这是视觉静止证据，不是对真实速度的直接测量。

接近障碍的地面轮廓明显不均匀时直接中止，**不绕障**。这些规则不保证识别任意障碍、颜色、照明、坡面或动态场景。

## 状态与执行反馈

控制状态：`observing → moving → braking → visual_stop`；缺帧、重复、乱序、过期/未来时刻、坏图、几何不可靠或超时进入 `aborted`。终止状态锁存，不凭后来一张好图自动恢复。

默认运动时限45模拟秒、制动确认时限3模拟秒、最大帧龄0.25模拟秒。制动意味着向轮电机请求零速，实际减速过程另行记录，不能假定瞬间停止。

| 新反馈 | 意义 |
|---|---|
| `completed_visual_stop` | 图像支持在前方横向阻挡处稳定停车，**未识别目标节点** |
| `aborted_motion_uncertain` | 已发出过运动命令，中途退出；不能假定原位或完整走过一条边 |
| `rejected_no_motion` | 本次未发出非零运动命令，不是旧原子反馈中的 `failed` |

所有结果均标记 `atomic_edge_compatible=false`。没有接入第五块会话，不向拓扑定位器谎报 `succeeded/failed`。电机请求与实际微小位移是不同量，初始沉降/制动也通过真值日志保留。

## 审计、日志和安全边界

每个新目录含 `run.json` 和 `frames/*.png`，记录所有控制周期的实际输入图像、哈希、帧元数据、故障、估计、v/ω、轮速目标、墙钟渲染/控制耗时。缺帧时保存本应采集到的图作诊断，`frame_id=null` 明确它**没有进入控制器**。

真值只用于刚体仿真、相机挂载和单向审计：记录实际轨迹、速度、朝向和碰撞，不能影响控制决策。碰撞在每个120Hz物理步审计，另保留10Hz采图时接触数；最终再用零轮速沉降1模拟秒，记录结果，不用它修补控制状态。

端墙审计要求视觉停车、实际相机到真实端墙0.9–1.7m、横向偏差<0.2m、偏航<8°、最终平面速度<0.03m/s、偏航角速度<0.03rad/s且全程无墙/障碍接触。它只是**评测器**；退出码可以使用审计结果，但控制器不能使用。

整宽中途阻挡与端墙可能在RGB中不可区分。本原型会停车，却不能知道阻挡的拓扑身份。日志的 `false_end_wall_claim` 表示“若把此视觉停车升级成端墙到达就会误报”，不是说反馈接口真的识别了端墙。必须单列这个失败，不能靠真值纠正决策后宣称视觉成功。

采集时刻、帧龄和超时使用同一**模拟时钟**；墙钟只记录实际计算耗时。同步仿真在渲染/处理期间不推进物理，10Hz是模拟控制频率，**不是实车硬实时或CPU吞吐保证**。尚无独立硬件看门狗、异步电机驱动或真实设备制动验证。
