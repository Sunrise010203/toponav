## 1. 已确认的项目目标与范围

### 1.1 一句话目标

**提供一张先验拓扑图，但不预先采集每个地点的照片；小车利用相机感知道路结构，结合地图、行驶历史和执行反馈进行定位与导航，在未参与训练的模拟布局中开展验证。**

这里的“跨场景”首先指本项目明确覆盖的室内正交通道、转角、路口等模拟条件，不承诺适应任意环境。

### 1.2 不再采用的主路线

- 不以 N01、N02、N03 等地图节点编号作为视觉分类类别。
- 不要求换一张测试地图就为该地图逐点拍照、重新训练节点分类器。
- 不把“识别出 T 形路口”直接等同于“知道具体位于哪个节点”。
- 不把地图中的目标角色当作单帧视觉必然可识别的类别。
- 不把原始 ImageNet 预训练模型的物体分类直接冒充导航结构识别。

旧节点概率版本保留为历史基线，不是待删除的错误代码。

### 1.3 第一版的工作假设

- 已知任务起点节点、目标节点及已确认的初始朝向。
- 地图提供节点连接和各通道出口方向；不要求逐点照片、精确几何坐标。
- 当前地图使用正交方向和双向简单图，暂不扩展任意角度、单向通行或平行边。
- 当前实际视觉实现使用前、左、右、后四向 RGB 视图；默认保留这一仿真基线，不为重做单前视而推倒当前成果。
- 四向输入的实车来源尚未证明：同时四相机、全景相机和单相机转动扫描不是同一方案。
- 当前执行器是原子转向加完整通道遍历，不是连续小车运动。
- 若后续使用里程计、深度、激光等辅助信息，必须显式声明、记录并保证对照一致，不能默默加入。

### 1.4 暂不纳入主线

## 4. 当前架构和不可破坏的接口

### 4.1 两条运行入口

```text
理想结构模拟：
StructuralEnvironment.observe()
  → update_candidates → decide
  → plan_from_estimate → next_action → execute

图像驱动：
PyBullet四向RGB → Predictor.predict()
  → packet.observation → update_candidates → decide
  → 公共规划/动作转换 → 离散execute → 下一次四向RGB
```

图像驱动版本不能偷偷调用理想结构传感器来修复模型错误。

### 4.2 地图与方向

- `graph.task`存放任务；默认任务为N01→N06、初始朝向0°。
- `node_id`只是地图身份，`node_type`只是结构属性，不是逐点图像标签。
- `graph.nodes[].exits`绑定neighbor_id、channel_id和direction，不靠并行数组猜对应关系。
- 绝对方向使用地图轴：east=0°、north=90°、west=180°、south=270°，逆时针为正。
- `scene.channels`提供物理通道两端向外方向；`scene.geometry`仅用于渲染、显示、标注和米制审计。
- 相对动作根据已确认朝向/进入关系和出口方向计算，不读取显示坐标差。
- v2规划按跳数：cost_unit=hops，length_m=null。不能把一条边当作一米；距离由可选几何另行评价。

### 4.3 结构观测：严格只有两个字段

```json
{
  "relative_open": {
    "front": true,
    "left": false,
    "right": true,
    "back": null
  },
  "confidence": 0.7
}
```

- true是观察到开放，false是明确不开放，null是未知；未知不等于关闭。
- 四方向相对于采图时小车朝向，不能用地图绝对方向直接填入。
- 当前低于0.6不按观测排除位置候选；不完整观测也不能继续运动。
- 当前顶层禁止额外字段。frame_id、采集时间、概率等在视觉旁路包中，不能直接塞入该严格接口。
- Softmax是未校准分数，不能把confidence=0.9解释为必有90%正确率。

### 4.4 位置估计与反馈

```text
位置候选：[{node_id, heading_deg}, ...]
运动命令：straight / left / right / uturn / stop
观测键：front / left / right / back
执行反馈：{"status": "succeeded|failed|unknown|sent|stopped"}
```

- 多个地点结构可以相同，需要历史和运动信息保持候选，不能直接取结构类别当节点。
- succeeded：当前模型中表示完成一次转向并走完整条通道。
- failed：当前模型中表示未平移也未转动。
- unknown/sent/缺失报告：保留原位与可能完成的候选并停止。
- 真实小车“转了一半/走了一半”不能报failed并套用原地未动假设；连续阶段必须另设计执行语义。
- 当前`update_candidates`接收上次动作和反馈；下一阶段必须在协调层防止同一完成反馈被重复应用。
- 起点和朝向来自任务先验，不用模拟真实状态初始化或修复定位。

### 4.5 视觉模型的真实结构

- 固定17类：exits_0000至exits_1111，以及unobservable。
- 四位顺序front、left、right、back；节点数量变化不改变输出维度。
- exits_0000是四向全封闭，不是普通单出口尽头，更不是到达目标。
- 输入为256×256 RGB面板：左上front、右上left、左下right、右下back。
- 各视图128×128、90° FOV；各自缩放至224×224后送入共享MobileNetV3-Small.features。
- 四视图各576维特征拼为2304维，接Dropout(0.1)和17类线性层。
- 使用ImageNet预训练，冻结骨干参数和BatchNorm，仅训练分类头；不是从零训练或骨干微调。
- 当前阈值0.6、在线帧龄上限1秒；缺视图硬检测主要识别全黑图，并不能检测全部遮挡。
- 必须传真实采集时间，不能每次推理时把旧图重新标记成“现在采集”。
- 模型只提供出口结构，不能据此假定距离、通道宽度、连续运动轨迹或碰撞安全。

### 4.6 真值隔离

允许：模拟器渲染、物理执行、离线标签生成及事后真实到达/距离审计使用真值。

禁止：定位/规划/恢复读取真实节点、真实朝向、坐标、真实到达标志来保证成功；利用纹理文字、节点编号、水印或文件名给模型泄漏标签。

目标到达要区分控制器判断与独立真值审计。错误到达必须记录为失败，不能由审计反向修改控制决策。

## 6. 完整实施顺序与每块验收

```text
1 地图（已有） → 2 规划（已有） → 3 结构观测闭环（已有）
                                         ↓
6A 最小渲染/采集（已有） → 4 视觉模型与图像离散接入（已有受限原型）
                                         ↓
5 持续观测、多帧确认、事件去重与恢复
                                         ↓
4B 必要的拒识/数据迭代（可与5交替，但须独立验收）
                                         ↓
6B 连续运动、相机与执行反馈 → 必要的ROS2联调
                                         ↓
7 公平对照、跨布局与外观测试、失败分析与报告
```

当前不重做1—3，不重装视觉环境，不以“先学完全部ROS2”为进入第五块的条件。

### 6.1 第一块：地图维护

**已有：** v2地图、任务/结构分离、显式出口、任意节点编号与不同数量案例、合法性与方向测试。

**后续只在新增场景时增量做：** 读取配对地图与场景，校验出口绑定与通道事实；当前地图假设变化时同步更新测试。

**验收：** 新编号/数量不改视觉类别；缺照片/几何仍可离散导航；非法引用、自连接、重复通道和出口错误被拒绝；关闭目标通道导致任务不可达不等于地图格式非法。

### 6.2 第二块：规划维护

**已有：** Dijkstra与当前公共规划接口，方向已知时相对动作，不确定时停止。

**后续：** 对恢复后接受的位置与新禁用边重新规划，不增加第二套绕过公共接口的规划器。

**验收：** 路线与出口一致；未知朝向不默认朝东；原来路不同导致的相对动作正确；关闭边不继续使用旧路线；地图不被函数副作用改写。

### 6.3 第三块：离散定位维护

**已有：** 候选节点/朝向集合、执行确认后转移、结构一致性与停止。

**后续：** 为第五块提供可重复观测调用，不让同一运动反馈被应用两次。先保留集合方法，不直接加入粒子滤波、复杂贝叶斯模型或POMDP。

**验收：** 同结构不同地点不会直接合并身份；连续帧不导致连续跨节点；执行失败与未确认不被当作成功；控制器不依赖真值。

### 6.4 第四块：保持基线并补足拒识

**已有：** 四向17类、正式数据、分类头训练与独立测试；图像驱动离散接入。

**待做：** 结合第五块时序有效性，定位遮挡/过渡错误接受来源；若需训练迭代，再扩充独立批次、设计新验证/测试布局。先保留模型v1，不直接覆盖。

**验收：** 类顺序与预处理可复现；坏帧、缺视图、未来时间与过期帧有明确处理；报告known accuracy、unknown false acceptance、拒绝率及覆盖率；不能以“全拒绝”冒充识别改善。具体性能目标应在新测试前锁定，当前没有宣称一个未经验证的安全阈值。

### 6.5 第五块：下一主要任务

目标：使系统在观测不确定时可以持续观测、确认、停止、有限恢复，而不是一停止就结束整个任务，也不在证据不足时盲动。

建议按5A—5F逐批实施，详见下一章。每批先运行旧回归，写出会失败的新增测试，再做最小修改，最后全回归与验收。

### 6.6 第六块：模拟器与连续控制

**6A已有：** PyBullet墙体、通道、RGB渲染与采集。此处不是完整动力学小车。

**6B待做：** 有实际运动状态的小车模型、速度/角速度控制、图像采样、通道跟随、转弯完成检测、路口进入/离开与安全停止。执行过程须能发生超时、偏离或部分移动，不再靠一步切换节点代替运动。

原则：先一个走廊，再一个转角，再T形路口，再多节点路线。沿用PyBullet可先做最小运动验证；如果模型、控制或渲染限制确需换平台，先提交方案，不在同一批同时维护多个模拟器。

**验收：** 动作改变实际位姿，改变后的图像驱动下一步；未使用坐标直达目标或节点瞬移；反馈来自声明的观测/控制完成条件；部分运动不套用failed=原地假设；碰撞风险或相机失联导致停车。

**ROS2后置联调：** 先确认纯Python链路稳定，再将感知、定位/决策、控制与反馈接成节点。旧练习消息是节点ID概率方案，必须按新契约有计划迁移；避免把帧元数据塞入现有严格观测字典。启动、参数、Topic与rosbag2可复现，不能以Topic有消息代替导航成功。

### 6.7 第七块：实验与成果

分别评价感知泛化、拓扑融合、恢复和连续控制。保持模型、传感器、控制器、目标定义和测试任务一致，只改变被研究机制。

优先比较：相同输入下的固定拓扑约束基线、带持续确认/恢复的版本及移除某机制的消融。若加入“无拓扑”导航对照，先定义可执行且目标信息可比较的策略，不让对照偷读真实位置，也不通过拿掉完成任务必需信息制造失败。

测试因素：新布局与节点数、材质/光照、遮挡与丢帧、错误识别、执行超时/不确定、地图边错误和临时封路。每次先单因素，再组合，不一开始全叠加。

**验收：** 任务与随机种子预定义；完整保存失败；性能选择只用验证条件；最终测试冻结后运行；明确统计分母、置信区间及不同实验单位，不能把同一布局的大量相关帧当作大量独立场景。

## 7. 第五块的可执行小任务清单

以下文件名是**拟议方案**，并非已存在。先检查项目风格再决定最终位置；不为一个功能创建过多抽象。

### 5A：会话与事件设计

- 阅读当前`run_navigation`遇stop就退出的行为，以及`update_candidates`消费动作/反馈的方式。
- 最小设计建议：新增协调器 `/home/sunrise/toponav_project/simulation/navigation_session.py` 与测试 `/home/sunrise/toponav_project/tests/test_navigation_session.py`，保留原入口为基线。
- 拆开“安全停止但仍可采图”和“任务终止”；定义导航、确认、停止观察、恢复、到达/失败等必要状态，不先铺满所有状态。
- 定义外层观测frame_id、采集时间、command_id及反馈事件ID。当前严格观测与反馈字典不直接加字段；由协调器消费外层元数据，或经确认后统一迁移所有生产者和消费者。
- 验收：明确状态转移表与事件所有权；设计能说明同一图像/反馈重复到达时怎样处理；提供至少一个后续可执行的测试用例草案。

### 5B：持续观测和时间安全

- 一个低可信帧先停止，但允许后续新帧到达；重复旧图不算新证据。
- 窗口最多计入一次每个frame_id；采集时间不新鲜、顺序错误等按明确规则处理。
- 用单调时钟做持续时间与超时，不用墙钟回拨决定任务超时；现有Unix采集时间用于帧龄时要声明同一时钟域。
- 验收：不确定→若干新鲜一致帧→恢复；持续缺帧→超时失败且不移动；同一帧重放N次不能获得N票。

### 5C：执行反馈只消费一次

- 发送命令不是成功。每个运动命令对应完成事件，完整通道转移最多应用一次。
- 第一次观测消费成功反馈后，后续同节点图像不能重复推进位置。
- 晚到、重复、不匹配或未知命令的反馈按规则拒绝/停止；不拿它们修正真实位置。
- 验收：同一成功反馈重放不会跨两条边；sent/unknown不推进为唯一成功；失败不产生虚构动作。

### 5D：多帧确认与路口防重复计数

- 先用窗口投票或概率平均一种简单方法，不一开始同时叠加多种滤波。
- 四向结构与参考朝向要对齐，转向前后的位编码不能直接混投。
- 视觉连续看见同一路口不等于经过多个节点；将“确认结构”与“确认完成节点转移”分开。
- 相邻帧错误可能相关，连续一致也不保证正确，不把投票数当作校准概率。
- 验收：短暂错误不会直接触发动作；同一路口持续曝光不重复计数；转向/离开阶段不会沿用旧结构推进位置。

### 5E：最小恢复与退出条件

- 正常时用历史候选；冲突时先停止重新观察。
- 有明确证据与策略时才扩大候选，如邻近节点/朝向，再考虑全图；不能清空候选后读取真值重置。
- 多候选仍不可区分时保持停止；不要求每次恢复一定成功。
- 第一版不自动盲目回退/掉头。若增加主动观测或运动恢复，必须验证可执行、安全和位置不确定下的授权条件。
- 用验证条件预设确认次数、最大重试和超时；不能在最终测试结果上不断挑阈值。
- 验收：可恢复例能恢复；对称不可辨例停止并报告；失败后不无限循环；错误到达会在审计暴露。

### 5F：接入真实视觉预测与回归

- 用现有Predictor旁路包驱动会话，不回退理想结构传感器。
- 模拟置信度错误、遮挡、丢帧与乱序；原模型已知拒识不足必须保留在报告中。
- 保留当前60项离散导航作为回归，不称为新的独立泛化测试。
- 验收：旧测试全部通过；新状态与事件测试通过；报告恢复成功/失败、等待时间、错误运动和停止次数，而非只看最终到达。

## 8. 实验记录必须包含什么

每轮使用新目录与run_id，不覆盖模型v1、旧清单、旧日志或封存测试。

最小记录字段：

- 代码版本或关键源码SHA256，模型SHA256，数据manifest SHA256。
- 运行环境、解释器、依赖版本、设备、线程数。
- 布局ID、split、起点/目标/初始朝向、传感器配置、随机种子。
- frame_id、真实采集时间、处理时间、拒识原因、结构观测与接受标志。
- 候选位置/朝向、状态转移原因、command_id、反馈事件及是否已消费。
- 重试、超时、恢复事件、规划变化、碰撞/停止/错误转向。
- 单向审计字段：真实轨迹、真实是否到达、真实距离；不得反馈给控制器。

指标定义：

| 指标 | 建议定义与限制 |
|---|---|
| 导航成功率 | 在预设步数/时间内真实到达且满足本轮安全条件的任务数 / 全部预定义任务数 |
| 误到达率 | 控制器宣称到达但真值未到达的任务比例，不能从成功统计中隐藏 |
| 已知结构准确率 | 已知结构样本的分类正确比例，另报每类支持数 |
| 不可观测错误接受率 | 不可观测样本中仍被当作完整可信结构接受的比例 |
| 接受覆盖率 | 被接受的观测 / 所有观测；防止全拒绝造成假改善 |
| 恢复成功率 | 预先定义的恢复事件中恢复成功的比例；说明超时与失败计入方式 |
| 恢复时间 | 明确定义从故障识别到恢复确认的时间；失败单独报告，不从统计消失 |
| 路径代价比 | 与同一可通行条件下最优路线比较；区分跳数比和米制距离比，分母为0/不可达时单列 |
| 推理延迟 | 分清纯前向、预处理+前向、整条感知控制链路；CPU/GPU设备条件分别报告 |

## 11. 后续AI的执行纪律

1. 先读当前适用指令和代码，再作假设；不清楚关键范围时问一个具体问题，不长篇泛问。
2. 每次只处理一个能验收的小任务；先说明输入、输出与成功标准。
3. 先运行相关旧测试；修bug先写能复现的失败测试，再最小实现，再全回归。
4. 不把“创建文件/没有报错/打印动作/Topic有消息”当成功证据。
5. 不改无关格式、删预存死代码或为了测试通过删除困难断言。
6. 不重新创建环境，不升级系统Python、显卡驱动、ROS版本或全部依赖。
7. 原始数据、模型v1与历史报告只读保留；新版本新目录；文件覆盖前核对并保留可恢复副本。
8. 当前根目录未见Git仓库元数据，不默认可以commit，也不擅自初始化Git；若后来已有仓库，先检查工作树，不丢弃用户修改。
9. 不自动向其他聊天发消息、创建新聊天或启动子代理；除非用户明确要求。
10. 不写入密码、私钥、Token等秘密；本文不含SSH私钥或认证材料。
11. 用户要学习：解释正在解决的问题，提供小任务、测试和排错方法，不一次生成难以理解的大工程。
12. 完成后更新实际进度，不把计划提前勾选完成。
