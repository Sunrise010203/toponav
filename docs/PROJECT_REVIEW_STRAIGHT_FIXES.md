# 项目检查：第三批修复——直走感知数值校验

日期：2026-10-29（Asia/Shanghai）。修复直走控制器对损坏的“已支持”感知输出的处理，不以降低视觉门槛换取运动。

## 复现与修复

1. **启动运动估计缺少数值校验**：原代码仅比较平移范数和偏航是否大于静止门槛。NaN的大小比较为假，因此带有`conditional_ground_motion`状态的非法估计可能授权启动探测；布尔值也可能被当作0/1。现在先验证二维平移和标量偏航的类型、形状及有限性，非法结果中止为`invalid_initial_ground_motion`，不发启动命令。
2. **前表面距离区间缺少校验**：已声明`conditional_front_surface`的区间若含NaN/Inf、布尔、字符串、缺失值、倒序或负下界，可能漏过停车判断、继续运动，或在读取时抛错。现在验证完整的非负有序有限二元区间，失败时立即零速并锁存`invalid_front_surface_interval`。不把畸形的“已支持”前表面默认为未知后继续行驶。
3. **静止证据统一检查**：停车及恢复窗口同样拒绝非法运动数值；它们不能累加静止票数、伪报视觉停车或恢复运动。原有等待/制动期限不延长。
4. **逐帧拒绝诊断**：`assess_startup_texture()`输出四个原有条件的检查结果、失败条件名称、原生和整流纹理支持数量；控制器保留三张启动帧各自的摘要，避免只展示最后一张好帧而掩盖前帧失败。

数值故障由**合成损坏的感知输出**注入，执行真实控制状态机复现；没有证据声称正常RGB生产者在旧实际运行中产生过这些NaN。这些测试验证防御性零速契约，不验证模型精度或车辆导航能力。

### 已知启动拒绝与近场限制

`diagnose_startup.py`只读第一批6m/seed313短测原始`sequence.json`声明的三张启动图，逐张验证原像素哈希，并与本批修改前的纹理函数比较。三张图都为九个原生单元通过、**仅五个整流单元通过**，低于原六单元门槛；逐格结果和接受状态原样相同。后续终态图没有替换到启动证据中。

另按既有完整原生补丁边界和默认安装做必要可见性分析：0.45m高水平相机、f64/c64时，每个方向最近完整补丁中心的前向深度约**0.505m**。对请求`v=0.15m/s, omega=0.1rad/s`、帧龄0、平移/偏航不确定度各0.002的保守扫掠，868个2cm单元中心在四方向都不满足完整补丁可见条件。此计算仅是安装可见性分析，不是RGB补丁接受、清障或无碰撞证明。

**这两项功能阻塞仍在，不能靠接受NaN或删掉近场未知区解决。** 后续需要明确的安装/近场感知方案及重新标定验证，不能保证仅靠有限代码修补即可完成普通直走。
