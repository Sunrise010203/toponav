# 第九批：直走启动拒绝诊断

日期：2026-10-29。**本批修复诊断遗漏，不宣称普通直走完成。**

## 实际问题

对既有6m、seed313、默认安装和原始纹理，显式确认初始净空并授权`bounded_probe`后，
真实PyBullet轮驱运行仍在三张启动图后以`startup_texture_unverified`零运动退出。
三张图都是原生9格通过、整流5格通过，低于原6格要求。

旧`tools/diagnose_straight_task1.py`只从启动后的新鲜几何感知中统计阻断项，导致这次明确的启动拒绝
被汇总为`blocker_counts={}`，`first_evidence_failure=null`。同时，控制输出虽然记录了三张图的计数，
却只有最后一张图的完整逐格结果，前两张图缺少时间、像素哈希和逐格诊断。

## 本批修改

- 启动纹理评估单独归因：与当前输入身份、采集时间、决策时间和评估时间绑定；旧同步记录只在同步条件下兼容。
  不把后续携带的缓存诊断算成新评估；汇总对相同三帧身份去重。启动拒绝也进入首次证据失败及阻断项统计。
- 三张图分别保留采集时间、原像素SHA256、检查布尔值及九格诊断；没有从后续帧中挑选通过结果。
- 新增`--recorded-run`只读入口，先验证公共序列与决策输入完全一致、路径边界和解码RGB哈希，再创建新诊断目录。
  缺失/损坏图、序列不一致、越界路径、空输入不会生成完成诊断；已有输出不可覆盖。
  不读取物理真值、不重新运行感知、不重跑物理，不把记录中的感知状态重新认证为正确。

用法（输出必须为新目录）：

```bash
cd /home/sunrise/toponav_project
.venv/bin/python tools/diagnose_straight_task1.py \
  --recorded-run /absolute/path/to/captured-run \
  --output /absolute/path/to/new-diagnosis
```

原历史再现模式保留；新入口不要求重新生成已经有RGB的旧运行，不补造缺失历史证据。
