# 第三十六批：订阅注册失败时拒绝启动

日期：2026-10-31。S2未通过、S6未完成，正式导航验收未恢复。

## 问题与修改

修改前真实`GazeboIO.__init__`配合明确fake transport，分别让概览、统计、时钟、姿态和五个接触通道的`subscribe()`返回False，九种情况均被忽略并继续创建执行器和步进助手。这是构造合同反例，不是自然原生注册故障或旧真实任务错误完成的证明。

本批只在原五处订阅调用位置增加返回值检查：前四处分别拒绝概览/统计/时钟/姿态，接触循环拒绝任一link的失败topic。首次失败立即抛`RuntimeError`，不继续后续注册、发布器、执行器或助手创建。原接收状态、方向/上下相机的检查及错误文本不变；成功时的消息类型、topic、回调、顺序和执行器参数不变。没有重试、替代通道、传感器降级、自动清错或新授权路径。

只验证注册API当次返回值；不能证明有发布者、数据持续到达、时间戳有效、来源真实、审计完整或无碰撞。启动在执行器创建前失败时，没有零速ACK或新鲜姿态证据，不宣称停车清理成功或物理停稳；仍按原runner取消控制器、记录失败并回收精确自有世界。
