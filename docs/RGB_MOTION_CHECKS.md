# 6B-1H：歧义拒识与低视差残差佐证

这是新增的只读模块，不替换G原型或旧控制器。输入仍只有公共RGB、帧ID、采样时间、标定ID，不用场景/位姿/深度/分割，不调用17类模型。物理通道/表面全部unknown，米制值null，运动不授权、到达未验证。

## 实际方法

1. 保留G的完整结果作同像素对照。对每个视图的原图/地面轨迹增加双向NCC局部描述，搜索完整处理画布中的竞争位置和自身重复位置；不是仅检查LK往返闭合。输出每条轨迹的实际得分、竞争峰、自相似、优势和拒绝原因。
2. 匹配预对齐单应只由拟合组坐标估计，过滤后保留固定分组。patch11px、NCC≥.70、匹配优势≥.06、自相似<.94；低对比度/边界拒绝。patch在地面分支的重采样画布计px，几何误差仍在原图计px。预对齐/重采样不完美，可能拒绝真实匹配，必须报告覆盖损失。
3. 新增上部固定y∈[8,80)图像假设，避免把侧墙与底部地面强制塞入同一单应。三帧坐标都需在该范围。按该矩形计覆盖格，仍≥6格；原图/地面沿用G规则。上部不是墙、地面ROI也不是已识别地面，真实俯仰失配时这些假设可错误。
4. 保留原单视图旋转竞争>1px，弱视差不能直接作高置信锚点。新建单独`anchored_support`：至少一个原有单视图流锚点，固定拟合/检查特征分组，共享R/t方向和各区域q联合拟合H=K(R+tqᵀ)K⁻¹，仅拟合点进最小二乘，检查点评估同一运动解释及相对纯旋转的改善。
5. 至少16点、拟合≥8/检查≥4；检查中位≤.75px、90分位≤1.5px、≤1px比例≥.8、相对纯旋转改善≥.20px，至少两视图/法线差≥20°；不收敛拒绝。输出每个区域、每对分解分支的通过/失败阶段及残差，并保留64条以内竞争解释及完整计数。严格共享/去上部区域结果另列，不能把多区域当独立样本。

**这不是“已经确定车在移动”**：共光心非双目，符号/尺度、cheirality和静态场景未验证。内部检查特征已经过同帧匹配和全区域筛选，并非整个流水线独立盲测；同一窗口内的候选组合也不是全9区域同一全局解。一次通过的含义是“至少一对不同视图区域在这些假设下有兼容解释”，不是唯一位姿、物理平面或到达。动态单墙/相机运动相同RGB的反例仍不能解决。

## 使用

```bash
cd /home/sunrise/toponav_project
export PYTHONDONTWRITEBYTECODE=1 OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2
.venv/bin/python -m roadvision.rgb_motion_checks_run \
  --manifest /absolute/public/sequence.json --rgb-root /absolute/public \
  --output /absolute/new-output
```

旧严格公共清单`rgb_probe_sequence_v1`、实际RGB字节SHA与PNG路径限制保持，最多缓存三帧，时间包络仍≤.25秒；输出不可覆盖。`windows.jsonl`保留全G对照、新轨迹、描述子证据、严格共享/残差佐证/消融和保守物理契约。`summary.json`分别统计严格共享及锚点佐证，不将两者混为导航成功率。

新评测入口：`python -m simulation.rgb_motion_checks_study --suite configs/evaluation/rgb_motion_checks_v1.json --freeze /absolute/freeze.json --output /absolute/new-study`。固定旧生成器→G独立预测→H独立预测→双方全部完成→事后审计。逻辑分隔，不是OS沙箱。模拟器只脚本设置相机/动态面，不是轮电机执行；快移不表示原车速度可达。

旧G的20条件是开发回归；新种子1337/9091的26条件冻结后首次运行。比较重复纹理拒识和正常覆盖损失、慢移支持和失败、动态反例与失配边界，不宣称普遍泛化或驾驶能力。具体开发尝试、门槛、分母见冻结前计划docs/plans/2026-10-15-rgb-motion-checks.md；最终结果单独写入进度增量和新报告，不改本说明的冻结内容。
