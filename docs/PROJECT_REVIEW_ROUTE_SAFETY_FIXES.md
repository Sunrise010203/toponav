# 项目检查：第五批修复——视觉路线输入与连续停车确认

日期：2026-10-29（Asia/Shanghai）。这是项目检查后的代码修复增量，不是直走五项冻结实验之后新增的正式实验任务，也不是Gazebo/ROS/S2/S6验收。

## 复现与修改

涉及`roadvision/model_route.py`中的模型闭环及`roadvision/landmark_route.py`中的标记辅助基线：

1. **坏包在保护范围外抛错**：原先在`try`和终态检查之前读取`frame['captured_sim_s']`，返回时又直接读取`frame['frame_id']`。缺包或缺字段可能抛错，活动控制器也未必进入中止态。现在先保护终态，再验证公开包字段；可预期输入错误返回零速并锁存`aborted`，标记相机也先检查数组类型再读取shape。
2. **时钟及身份校验不足**：拒绝布尔、非有限、非数值、负时间和会导致有限性检查溢出的超大整数；增加决策时钟单调检查及已见身份去重，不再只检查与上一帧ID不同。有效输入仍沿用原来的`0 <= now-captured <= 0.250001`和采集时刻严格递增条件，不延长期限。
3. **终态隔离不完整**：`visual_stop/aborted`直接返回缓存绑定的零速快照；后续坏包、NaN时钟或新帧都不能改写终态、节点事件或运动计数。非法包头不写入输出时间/身份，避免将NaN带进严格JSON日志。尚无有效包头时保留空身份/时间哨兵，不伪造有效相机证据；独立MotorGate仍会拒绝无效命令并停车。
4. **非预期感知异常**：先锁存中止并清除确认票数，再向调用方传播原异常，不吞掉后端故障。已有Gazebo执行器的`finally`停车和MotorGate租约保持不变；测试不把控制器锁存等同于真实传输已发布停车。
5. **模型停靠跨证据丢失累票**：原来两次稳定零速后，即使模型拒识/结构不匹配或站点几何丢失，票数仍为2，下一张好帧便可发出停车事件。现在这些hold分支清零，必须重新取得三张连续有效的稳定零速帧；随后仍需另外三帧模型确认才能更新节点。原停车距离、偏移、角度、超时及三帧门槛都不放宽。

模型模式只接收`frame_id/captured_sim_s/rgb`；标记模式接收相同时间/身份和`up_rgb/down_rgb`，兼容执行器额外携带的主`rgb`。额外真值字段不接受。两种模式没有互相回退。
