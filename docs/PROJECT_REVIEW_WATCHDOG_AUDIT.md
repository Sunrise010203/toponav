# 第十四批：独立执行端的阻塞审计隔离（P0补漏）

日期：2026-10-30。上批将速度发布与导航/GIL/步进助手隔离，但执行端自身仍同步写日志；
`write/flush`遇到存储阻塞，会让同一进程无法检查原0.8秒期限。本批修复这一具体失效路径，
**不是执行进程被杀、OS挂死、原生发布永久阻塞或底盘硬件故障的修复。**

## 修改

`simulation/gazebo_actuator.py`：

1. 独立日志子进程只持有日志FD与私有SOCK_SEQPACKET端，不导入原生Gazebo，不持有命令管道、
   不发布速度。使用exec子进程而非对已启动原生线程做Python fork，也不依赖线程争用GIL。
2. 执行端仅非阻塞投递审计记录，最多64条待确认；写端逐条write/flush后确认对应序号。
   退出、坏确认、管道满、队列满或最老待确认超过0.4秒均失败锁存零速，不无限排队或重试。
   **0.4秒仅为审计健康预算，不是运动租约、续租心跳、fsync或永久落盘证明。**
3. 原运动命令仍以原issued时刻+.8秒为上限；未确认日志、导航恢复或存储恢复均不能续租/解锁。
   看门狗轮询期间不做磁盘写入；故障后继续重复零速。启动握手可等待，但当时尚无运动权限。
4. 最终已锁存/发布零速后，有界排空日志并回收自有日志子进程；SIGSTOP写端也不会无限卡住退出。
5. 新增审计摘要校验：必须有ready到worker_exit的完整日志、最终锁存零速和有效字段。
   缺失、残缺JSON、坏字段或只有合法前缀都保留故障，不因缺少末尾故障记录而误报任务完成；
   解析失败写入结果，不再直接抛异常丢失整个结果报告。原始日志不修补/覆盖。

原MotorGate/0.8秒期限、0.15m/s与0.30rad/s限速、几何/静止判据、RGB控制器、地图、相机、
模型与0.6识别门槛均未改。仅执行模块、运行器摘要接入、README、新文档与新测试发生修改。
