## 读取规则

- 总原始输入上限16MiB，最多额外读取1字节探测超限；不使用整文件读取或依赖文件大小元数据判断完整性。
- 单个LF物理块最多16384字节，包含结尾LF；最多缓冲该上限加1字节，超长/未终止块不会进入UTF-8或JSON解析。每次底层读取不超过8192字节。
- 最多65536条逻辑记录，保留完整前缀；下一条不做JSON解析、不淘汰旧记录、不搜索末尾的安全终态。
- 在有界LF块内保留旧`splitlines()`语义，兼容CRLF和旧分隔符；仍要求最终LF，重复键/坏JSON/非finite/不合法历史/末态不绑定等原门槛不放宽。
- 文件用`O_NONBLOCK|O_NOFOLLOW`打开，`fstat`仅允许普通文件；FIFO/目录不读、不跟随链接；解析错误也显式关闭生成器及文件描述符。
- 超限抛出原摘要路径可处理的错误，`audit_complete=false`、`fault_latched=true`，不能支持完成。先检查故障补充文件；若格式无效或不可读则立即拒绝，不再打开主日志，明确披露`read_attempted=false`、未绑定、0条保留，不能声称已校验主日志。不存在或合法的sidecar仍执行原主日志历史校验，主日志错误优先于合法故障诊断。
- 新增`audit_history`披露上限、实际读取字节、保留记录数和三类超限标记。读取字节可能含尚未解析的预读；保留记录数不是全文件记录总数，前缀末态不是最终授权证明。

普通文件/NFS的操作系统I/O仍可能阻塞，`NONBLOCK`不等于硬实时。此处只限制摘要输入、单块和保留记录；不限制运行时审计写入/磁盘/传输/接触/图像或全进程总内存，也不提供持久化或来源认证。
