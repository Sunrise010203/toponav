## 1. 时钟来源审查，必须区分两条执行路径

|现有路径|可证实的时间来源|不能推出的结论|
|---|---|---|
|Gazebo `GazeboIO.image` / `CameraBuffer`|图像header中的原模拟戳；缓存按相同模拟戳拼接四视图，路由另有up/down|未记录曝光墙钟或回调入口墙钟；相同模拟戳不等于同一墙钟采集年龄|
|Gazebo `next_frame` / 主循环|返回模拟采集戳与当前模拟时刻；`controller.update`之后才arm并签发issued|签发前计算、PNG写入、同步缓存等待没有因此获得采集墙钟上界|
|ROS `Navigation.image`|`last_delivery=time.monotonic()`是该回调中的主机交付观察，不是曝光戳|上游排队/网络延迟未知，不能用交付时刻倒推出曝光|
|ROS `World.frame`|capture后、PNG保存/DDS发布前已经在独立world进程arm；`World.timer`检查pending与hold|ROS已有计算前pending守卫，不应把Gazebo签发缺口泛化为所有路径；capture函数自身与world/OS卡死不受其独立保障|
|`MotorGate` / `LeaseGuard` / 原生`ReceiverLease`|同主机单调时钟下的绝对期限；原生接收端校验issued/expires不超过0.8s|原生接收端目前没有可信曝光区间或计算前token，单靠新增调用方字段不能证明下游已绑定采集期限|

`Navigation.tick`的0.6s交付超时在导航同进程内，计算阻塞时不是独立看门狗。
ROS world独立pending/hold守卫与Gazebo独立执行/接收端不能互相替代证据。
公开保存的RGB只保留模拟采集戳；历史墙钟曝光时间仍不可恢复。

## 2. 拟议的可信证据链（目前没有真实提供者）

每个**配置要求**的视图：原模拟/设备戳、像素SHA256、主机回调入口时刻、解码完成时刻分别保存。
真正的曝光墙钟必须来自驱动器曝光元数据，或有误差界、有效期和时钟域/boot身份的可核验映射，
表达为`[exposure_lower, exposure_upper]`。回调入口只是交付观察；`receive-0`不是曝光下界。
未知上游时延时，接收戳最多提供曝光上界，**不能**证明图像足够新鲜。

- 缺失曝光下界、时钟域不匹配、映射过期/无界、未来/NaN/回退、缺少任一必需视图：拟议运动路径拒绝。
- 需要视图集合来自冻结的owner配置，不能让计算端删掉陈旧视图后只提交新鲜子集。
  当前摄像路径最多四视图加up/down共六路。模型只验证区间数学与绑定，不验证实际传感器。
- `bounded_exposure_mapping`在影子数据里只是**明确的合成标签**，不是真实性认证。
  构造dataclass或提供nonce不构成可信来源；真实提供者、像素与元数据不可替换绑定、权限隔离尚未实现。
- 控制器不能自行填写曝光下界、签发时刻、expires，也不能修改owner注册表。

## 3. 拟议状态机与不延长预算的公式

仍使用原0.8s租约作为本方案候选的**上限**，不是已批准的墙钟图像安全年龄。
原0.1s计算目标、0.25s模拟年龄、0.4s日志ACK和所有限速/制动/恢复预算均不改。
该上限还须与原制动距离/初始净空等约束一起审查，不能因小于0.8s就称安全。

由独立owner在计算开始前持有原始证据并生成一次性token，绑定会话、帧ID、模拟戳、全部必需视图像素摘要：

```
D_frame = min(每个必需视图的 exposure_lower) + 0.8
D_effective = min(D_frame（若pending）, D_hold（若有已接受命令）)
```

计算/等待/传输均消耗同一`D_frame`。`now >= D_effective`立即锁存，不设观测容差续租。
结果在该期限前到达并匹配token/绑定，owner才形成影子许可：

```
issued = owner_now
expires = min(D_frame, issued + 0.8)
```

新pending不能延长旧hold；旧hold到期必须先锁存。
如果新结果确实在旧hold和自身frame期限前被接受，可用该新帧剩余预算替换旧hold，这是原有及时换帧语义，
不是永远把所有后续帧裁剪到第一条命令的期限。
已消费token/帧不能复用，pending不可覆盖，到期后新帧/新序号/新issued都不能解锁；容量耗尽不淘汰旧证据。
停止不需要新帧、正常零观测不能被当成解锁或续租心跳。

`DeadlineProposal`只演示这些数学/状态不变量；不接受速度，也不调用执行器。
`ShadowPermit`并非生产命令或可验证授权凭证。现有`LeaseGuard`接受较短expires的兼容单测，
仅证明原算术已经允许缩短期限，不证明整条原生接收链已经绑定token或采集来源。

## 4. 独立性与反例

六例各三次，正/反/正序串行：未知曝光、首次慢计算、旧hold+新pending、结果重签时间、区间不确定性、owner自身暂停。
所有曝光区间为合成同主机monotonic，所有计算延迟为1.1s注入sleep；不是实际相机或控制器工作。
生产执行/接收暂停证据沿用上一轮的冻结工件，不重跑成新的导航结果。

影子owner在另一个进程中按原20ms轮询，不依赖计算端轮询。观测容差0.15s不进入任何期限算式。
owner自身SIGSTOP时，**预期出现晚锁存反例**，绝不能以恢复后的锁存算原期限内停车。
即使已经记录绝对期限，停止的owner/接收器也不能执行轮询；仍需要独立底盘接收端/固件看门狗和真实制动反馈。
影子日志同步写文件、Python/OS调度也都可能阻塞；这不是生产安全循环实现或硬实时上界。
