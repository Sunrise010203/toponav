日期：2026-10-31。S2未通过、S6未完成，正式导航验收未恢复。

## 问题与修改

修改前使用真实旧生产回调和512×512合成RGB消息，方向相机先把786432字节交给NumPy并复制，再因尺寸不符拒绝；概览回调直接保留512×512图像，没有尺寸门槛。旧方向回调还会覆盖更早的I/O错误，概览解码错误则直接逃逸回调。这个反例不是实际传感器故障、自然IPC压力根因或旧任务误报完成的证明。

本批只修改`simulation/gazebo_cross_validation.py`的图像入口、首错误保留、已知错误非零拒绝和事后完成拒绝，另增测试及文档。方向相机128×128、上下相机256×256、概览384×384或768×448仍与原场景一致，没有修改相机、地图、像素、控制器、原生执行器或物理步进策略。

- 通用`pixels()`在访问载荷前验证正整数宽/高、最大宽768/高448、调用方声明的精确尺寸白名单、RGB_INT8枚举及恰好`width*3`的整数步长。未知枚举统一拒绝。错误尺寸/格式/步长不获取`data`、不创建NumPy视图或副本。
- 元数据通过后只获取一次`data`，长度必须恰好`height*step`，之后才创建uint8数组并复制。通用解码单次成功的像素副本最多1032192字节；不是原始消息接收、protobuf字段访问/分配、总内存、调度时间或硬实时上限。
- 概览只接受原384×384或768×448两种尺寸，不接受其它宽高组合。方向回调先拒绝未知view，使用对应128/256精确尺寸。保留合法像素的原始值和原始采集时间，不缩放、填充、裁剪、改时间戳或回退到旧图恢复运动。
- 方向和概览回调均捕获解码异常，保留原`self.error`首故障并通知等待者；概览失败时清除旧概览图。后来合法图像仍可按原路径留存，但不能清除首故障或重新授权。
- 原非零提交在保留姿态/接触容量检查之后、接收反馈/执行通道访问之前拒绝已知I/O错误。零速/STOP路径不受此新检查阻拦。概览仍不作为驾驶输入；概览故障保守否决任务，不把它变成导航证据。
- 事后若没有更早执行异常、姿态或接触不完整错误，则把残留I/O回调错误写入主异常，防止末次清理阶段才出现的错误漏过完成门控。不覆盖主异常，也不把图像故障等同于姿态失效：原新鲜姿态确实证明的停稳事实仍保留。

原完成表达式、十步停车清理、独立失败通道观察、租约0.8秒、队列64项、审计超时0.4秒均不改。没有新重试、降级、续租或自动清错。
