# 普通直走：描述子匹配临时工作区

**该候选未推广，默认生产实现已恢复为第06轮原字节。** 组合优化在冻结后正横偏控制器前缀测量中退化，不能用局部改善声称整体提速。

候选保留于`roadvision/descriptor_scratch_search.py`，内容与实际测量的候选实现相同；默认入口、S2包装器、独立S1、控制器均不导入此模块。仅新增测试显式选择候选。所有既有源码/测试/配置恢复或保持原字节。**S2未通过，S6未完成**，默认`no_motion`。

## 保持原计算

- 每条有效轨迹仍执行四次完整`cv2.matchTemplate(..., TM_CCOEFF_NORMED)`，没有缓存/跳过评分、缩小搜索范围、重选点或阈值修改。
- 二维整数网格换成横/纵一维坐标，逐元素仍依原顺序执行减端点、平方、相加、比较半径；广播不改变每个像素的计算。
- 每张画布建立一张float32输出缓冲、一张bool有效性缓冲。每次完整匹配重新写入分数；`isfinite`及排除/支持范围完整覆盖有效性缓冲，不读取上一轮结果。使用OpenCV实际返回的结果，不假定返回对象身份。
- 掩码路径用`count_nonzero(bool)`取得与原bool求和相同的整数；仅在非零时执行原顺序的`score[valid].max()`，不改最大值归约、NCC或margin计算。
- 支持腐蚀、整流否决、训练/留出划分、模型、控制和运动权限保持原样。

这只是输出/有效性工作区，不代表OpenCV内部不再分配临时空间。上下文与缓冲仅用于一次区域调用中的**同步、非重入**搜索，不跨帧/区域持有、不共享给其他线程或返回证据。即便两次模板相同，也仍执行两次完整匹配。搜索返回的是标量/计数，不外泄可被下一次覆盖的数组。

## 验证方法

先采集当前实现的22条已暴露控制器输入剖析；再保留分离坐标、缓冲复用及组合的开发试验。开发试验只用于选择，不冒充冻结候选正式测量。

测量候选冻结后，对备份第06轮实现与候选交替预热测量，逐项核对分数、有效计数、失败原因、模型和控制输出。新测试额外污染缓冲、交错调用已保存端点闭包、输入非有限分数并核对同一工作区被完整覆盖；既有132项准备路径测试继续运行，尤其保留每轨迹四次实际匹配断言。

冻结后局部过滤中位耗时减少5.66%；中心控制器前缀减少5.36%，但正横偏增加16.69%（四轮中位数均不利）。运行时况/实现原因未证明，不删异常轮次或重测到通过。候选因此未推广。原计划10组回放主动中断，只将进度文件中完整结束的3组计为通过；进行中的条件不计完成，也不谎称做完候选全量测试。原测量冻结、3项被演进文件的原字节快照、终止记录和后续最终源码冻结同时保留。

隔离后另跑针对性和普通全量测试，明确区分“实验候选回归”与“最终默认生产交付”。后者验证恢复的旧生产代码及新增显式实验测试，不是候选获得默认接入资格。

性能只属于所列已暴露输入和前缀；不代表10Hz达标、导航完成或实车制动证明。没有专门物理验收。窄障碍覆盖、近场未知及第05轮IPC超时未定根因问题均不因此修复；不放宽任何安全预算。
