# IPC 超时分阶段诊断（仅按需启用）

第05轮全量软件测试中，原8193次零速IPC检查在第6930次观察到ACK发布后约1.068秒才完成客户端接收。原0.8秒截止正确拒绝了它；三次独立复核通过并未修复或撤销该失败。现有证据无法认定是GC、调度、提交记录、socket或解码导致。

新增工具不被导航运行时、普通pytest或全量测试脚本自动加载。只包装一个**已启动、单线程同步调用**的客户端，不改生产源码：

```sh
.venv/bin/python -m tools.actuator_ipc_diagnostics --output /绝对路径/新的诊断目录
```

固定执行一次原来的8193次零速测试，不重试到通过；保留命令、原测试日志、JUnit、源哈希、GC状态和阶段数据。此处有真实worker/socket和合成帧元数据，没有原生接收器、RGB/物理或运动验收含义。测试仍按原规则在第8193次记录接收器候选容量故障，验证零速、停止及退出能力。

## 观测边界

- 原`request`、`_receive`、`_validate_ack`继续执行，逐个转发同一socket调用、参数、返回值和异常；原0.8秒等待及绝对命令截止均不变。
- 不替换传给原ACK验证器的接收时刻，不把诊断时刻用于授权；不修改观察器、门槛、GC启用状态/阈值或触发收集。
- 记录编码/发送、发送后提交记录、等待、recv、解码、验证、提交返回以及失败关闭的本地时刻。`wait_done`是原select返回到调用recv之间的客户端时刻，不是内核ACK到达时刻；`decoded`包含包装开销。
- GC回调只聚合本调用线程实际观测到的0/1/2代收集次数、总耗时和最长暂停所在阶段，不保留对象或逐事件清单。其他线程的GC和宿主调度停顿未被完整测量。
- 每个probe仅留最近64次请求及最长一次，无报文、ACK内容、异常字符串、图像或所有请求历史。计数饱和，JSON不超过256KiB；丢弃数量显式报告。此限量不代表整个pytest进程内存有界。
- 原失败路径先关闭通道；此后才封装最终记录。离开上下文恢复实例属性并移除自己的GC回调，不移除别人的回调。文件写入在测试会话结束、fixture清理后完成。

**诊断增加时钟读取、包装、分配和GC回调开销**，可能改变时序，不能用作无仪器延迟基准。单次未复现不能证明修复；即使某次观测到同阶段GC，也不能反推第05轮旧失败根因。正常无仪器全量测试必须单独保留。

工具不改变控制器、RGB判据、默认`no_motion`、速度、制动或恢复预算。S2未通过、S6未完成；实时预算、窄障碍覆盖和近场盲区仍未解决。
