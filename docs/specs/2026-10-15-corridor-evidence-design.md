## 1. 为什么下一步不是直接转角

冻结验证保留了25个新条件与1个旧对照。三例视觉停车失败揭示的是不同问题：

| 案例 | 已保存的审计事实（不是在线输入） | 需要分开的含义 |
|---|---|---|
| gray_paint_suffix | 没有新增立墙，距真实端墙仍3.502m | 地面材质边界不等于竖直阻挡 |
| offset_blue_paint | 距端墙1.299m，但真实横向偏差+0.257m | 涂色中心不等于物理通道中心；此例不是端墙距离失败 |
| new_full_barrier | 中途整宽阻挡停车，距端墙仍4.406m | 阻挡/停车不等于目标节点身份 |

此外2.2m、2.6m宽走廊靠近端墙时退出，最后有效拟合仅6行；不能靠降低内点门限声称解决可观测性。详细原证据见 `/home/sunrise/toponav_project/reports/corridor-validation-20261015-fR5B4u/RESULTS.md`。

本轮不调颜色、拟合、停车阈值，不改变运动或审计。旧失败依然存在。新增接口只能防止**声明层**把颜色直接标成物理几何，不能检测一个谎报 `rgb_temporal_geometry` 的生产者。

## 2. 观测边界和可观测性

允许：现有四向RGB、采集身份/模拟时刻、预先固定的相机内外参和安装高度。禁止：深度、分割ID、接触、地图节点/坐标、模拟器位姿/速度、轮编码器、IMU、审计结果；也不调用17类结构模型作为几何证明。

四向相机近似同光心，提供方向覆盖，**不是有基线的立体相机**。不同朝向同时拍摄不能直接三角测距。轮速命令不是里程计，也不能证明真实平移。时序几何需要图像中可验证的平移/视差和稳定特征。

| 条件/证据 | 最多可支持什么 | 不能据此得出什么 |
|---|---|---|
| 单帧颜色/区域边缘 | appearance candidate | 地面身份、墙面、通道宽/中心、到达 |
| 固定相机与已知平面上的射线投影 | 在假设成立时的条件几何 | 所有颜色区域就在地面上 |
| 多帧地面单应拟合 | ground-consistent候选 | 唯一地面解释；平面单应也可能来自立墙或纯旋转 |
| 有足够平移视差的稳定特征、竞争平面解释、跨时刻一致 | 可能支持地面/非地面候选 | 普遍唯一分解、目标身份或自动运动授权 |
| 双侧物理边界候选且尺度可观测 | 有条件的横偏/航向候选 | 涂色中心就是通道中心 |
| 前方非地面候选 | 可能存在需避让的表面 | 它一定是端墙或目标节点 |
| 纯旋转/静止/低纹理/重复纹理/视差不足 | unknown | 不能用命令速度补出基线和距离 |
| 时间戳变化且RGB哈希不同 | 元数据的必要条件 | 真实视差、几何正确、可信采集源 |

米制尺度只可在已声明的标定和可验证几何约束下估计。已知安装高度并不自动解决任意图像的尺度。若仅有相对结构、无法可靠恢复米制横偏，v1的 `corridor_boundary` 必须为unknown，而不是填0；前方非地面候选可令 `range_m=null`。

**近水平、固定安装的相机假设必须公开。** 后续实验只在预先限定的平整地面/安装范围内讨论；一旦图像证据不支持该假设，输出unknown。不能通过读取模拟器俯仰/横滚或新增IMU静默校正。标定ID相同只是配置一致性检查，绝不是标定误差已验证。

## 3. 已实现的证据声明契约v1

入口 `review_corridor_evidence(packet, *, now_s, calibration_id)` 是纯声明校验，不读图，不读取世界状态，不发轮速。所有对象都只允许下列字段，未知/多余键拒绝。无输入变更。

```text
packet:
  version: "corridor_evidence_v1"
  evidence_id: 非空字符串，最长256字符
  calibration_id: 非空字符串，必须等于调用方预期ID
  frames: 1..16条严格按采集时间递增的引用
    - frame_id: 非空字符串，最长256字符，包内唯一
      captured_sim_s: 有限JSON数值，不接受bool
      rgb_sha256: 64位小写十六进制字符串
  appearance_boundary:
    state: unknown | candidate
    method: none | rgb_colour
  corridor_boundary:
    state: unknown | candidate
    method: none | rgb_temporal_geometry
    views: front/left/right/back的无重复列表
    offset_m: null | 有限数值
    heading_rad: null | 有限数值，绝对值不超过pi
  front_surface:
    state: unknown | ground_consistent | non_ground_candidate
    method: none | rgb_temporal_geometry
    views: front/left/right/back的无重复列表
    range_m: null | 有限正数
```

### 字段组合约束

- 外观unknown配none；candidate配rgb_colour。外观证据不自动升级为几何。
- 通道unknown要求method=none、views=[]、两个指标均null。
- 通道candidate要求method=rgb_temporal_geometry、同时声明left和right支持，且两个指标非null。这里是候选生产者的声明，不是校验器看过双侧像素。
- 前方unknown要求none、[]和null；另两种状态要求rgb_temporal_geometry及front支持。
- ground_consistent必须range_m=null：地面变化不提供障碍距离。
- non_ground_candidate的距离可null；有距离也不是目标身份。
- 任何几何声明要求至少两个不同采集时刻及至少两个不同RGB哈希。所有引用均要求采集时刻非负、不晚于now_s、帧龄不超过0.25模拟秒；now_s也须有限非负。0.25沿用旧实验时间包络，不是新的几何成功阈值或实车实时保证。
- 每个ID最长256字符；包内重复帧ID、重复采集时刻、乱序拒绝。**没有跨包事件去重**。同一RGB在不同时间出现本身并非非法，只有几何声明不能全部是同一个哈希。
- truth、pose、node_id、depth等任何额外字段拒绝；这限制输入通道，不证明调用方没有在外部使用真值造声明。

建议未来生产者统一把每个采集时刻的四向完整RGB拼图按uint8、C顺序原始像素计算哈希，不把PNG编码字节哈希当像素哈希。当前仅检查哈希格式，不读取或比对图像字节；帧引用也没有逐特征/逐视图绑定。未来生产者必须另留只读追踪、残差、模型选择和退化诊断记录，建立图像、标定、窗口和各视图的可审计绑定后，再讨论更强的协议。合成测试中的ID/哈希只是协议样例，不是采集数据。

候选指标的建议坐标约定：横偏为相机/车体中心相对物理通道中心向左为正，航向为车体前向相对通道前向向左为正（弧度）；range为前向光轴沿行进方向与候选表面的交点距离（米），不代替完整车体碰撞包络。真正生产者实施前必须把相机到车体变换、有效区域和误差界写入标定说明并测试；本轮没有生产者可证明这些指标。

### 固定保守输出

```text
corridor_geometry: unknown | candidate
front_surface: 原声明的合法状态
review_notes: 说明颜色/地面变化/表面身份的限制
motion_authorized: false
arrival_status: "unverified"
atomic_edge_compatible: false
```

合法candidate仍不授权运动。这是尚未接入控制的协议原型，**不是用“始终停车”冒充改进后的安全导航**。当前生产入口均不调用它，原车动作不变。

## 4. 运动停车、位姿确认、节点到达分层

入口 `split_motion_feedback(feedback)` 只允许原连续运动公开的三个字段：`status`、`atomic_edge_compatible=false`、`motion_was_commanded`（必须bool）。不允许把整个run.json、审计、场景或节点作为载荷送入。

| 原公开status | 新motion_outcome | 解释 |
|---|---|---|
| completed_visual_stop | visual_stop_supported | 原模块报告视觉停车，不独立证明实际位姿 |
| aborted_motion_uncertain | motion_aborted_uncertain | 已发过运动命令，终态不确定 |
| rejected_no_motion | not_commanded | 此次没有发运动命令，不代表已经定位到节点 |

其余固定输出：`pose_status=unverified`、`arrival_status=unverified`、`atomic_edge_compatible=false`、`legacy_feedback=null`。rejected却commanded=true、aborted却commanded=false均拒绝；起步已满足视觉停车条件的completed且commanded=false允许。

旧原子failed的含义是既无平移也无旋转。连续运动中止后可能在任意中间位置，不能套旧succeeded/failed；甚至旧unknown的“原位或走完整边”候选集合也不覆盖中间位姿。新原型不调用第五块会话、不推进候选节点、不添加旧反馈转换器。将来真正接入需要连续位姿/边进度的不确定性模型、事件与命令绑定和跨事件去重，不能只改状态名字。

拓扑到达还缺可靠的节点身份/结构、连续定位关系与独立的确认机制；本轮没有定义“非地面表面=dead_end节点”。即使事后端墙停车审计通过，也不能从公开运动反馈自动获得这些信息。

## 5. 下一最小实现：只读RGB序列可行性探针（尚未实现）

目标不是立刻开车，而是验证现有RGB里是否有足够信息区分几种解释，并在不足时诚实拒绝。

1. **输入冻结**：仅读取保存的RGB及身份/模拟时刻、预声明标定。独立保存输入白名单，禁止读控制结果、场景、节点或audit后再产生候选。旧案例名称仅用于离线报告索引，不能成为特征。
2. **特征追踪**：在front/left/right各自图像内追踪跨时刻特征，记录覆盖、往返一致性、寿命、遮挡及明显动态点。不同视向不是立体配对；同光心不假装有基线。不要把照明变化形成的不同哈希当运动。
3. **竞争解释**：评估纯旋转、地面平面和其他平面/非平面解释。对拟合外点、残差和模型歧义留证；单一单应拟合良好不能独立证明地面。用图像估计的相对运动/视差验证平移是否可观测，不用轮速积分补足。
4. **双侧与跨时一致**：物理通道候选依赖左右视图中的几何证据，而不是蓝色条带边缘；前视支持前方表面候选。检验合理的跨时预测和模型竞争；不要求低纹理场景必然可解。
5. **显式退化**：静止、纯旋转、纹理缺失、重复纹理、视差不足、光照变化、严重遮挡、模型分解多解、标定假设不支持时必须unknown。可以整段unknown，不为提高覆盖率填距离/横偏。
6. **离线记录**：同时保留接受与拒绝的图像、轨迹、诊断和耗时。若相机模型不足或需要更大时间窗，先修订设计并冻结实验，而不是绕过0.25s包络。现在没有承诺具体追踪器或参数能在这批画面上成功。

开发前先声明如何选取纹理/平面/视差支持及误差阈值、哪些字段能够输出、拒绝标准与计算预算。阈值只在开发划分上确定，冻结后不得按验证真值调整。没有足够证据的结论可以是“现有配置不足”，而不是必须交付一个总能测距的算法。

## 6. 后续验收矩阵与接线门槛

| 测试族 | 必须检查的行为 |
|---|---|
| 地面涂色/纹理变化（无立墙） | 不能仅因颜色边界输出已证明的墙；不能认定到达 |
| 偏置涂色与双侧真实墙 | 不能沿涂色中心声称物理居中；无双侧几何时unknown |
| 端墙与外观相同的中途障碍 | 最多表面候选；两者都不能仅凭停车认定目标身份 |
| 宽走廊/侧边离开视场 | 证据不足显式拒绝，不降低可靠性换取通过 |
| 静止/纯旋转/极小平移/无纹理 | 不用时间戳、哈希变化或轮速命令冒充视差 |
| 重复纹理/阴影/色温/遮挡 | 保留歧义及误匹配，分别报告错误接受与拒绝 |
| 错误标定/乱序/重放/过期 | 协议错误拒绝；正确ID不代替真实标定测试 |
| 非地面但无尺度 | range=null，而不是虚构米制距离 |

协议单元测试只能检查组合和语义，不能代替上述图像负例。几何可行性验证需单列候选覆盖、错误接受、拒绝/未知、横偏/航向/距离误差和适用条件；离线审计真值仅用于最终独立评价，不反馈生产者。不能只汇报“安全”或“全拒绝”而隐藏覆盖不足。

旧25条件一旦参与开发就成为开发回归，不再声称是修正版的独立新验证。下一轮应预声明未用于调参的新条件并冻结代码/阈值后运行，保留所有失败。本轮不采集新训练集，不训练、不增传感器。

在只读证据和退化拒绝可复验之前，不接轮速。之后若另行实现控制接线：缺失/坏/过期证据不得继续正速度，需零命令和制动/超时状态；制动确认仍不是节点到达，必须另做动态验收。这个要求目前只是设计，并未修复旧控制器。再之后才讨论受限单转角、连续拓扑接入、ROS或实车。

## 7. 本轮验证的确切含义

新增44项测试使用合成协议载荷，没有提取真实几何。另只读转换全部26例旧公开反馈，包含旧对照与所有失败：14次视觉停车、5次部分运动中止、7次未发令，全部位置/到达unverified且无旧反馈转换。包括事后审计通过的11例也不放行，避免借真值只拦坏例、放行好例。

这验证的是协议与语义边界，不是新图像算法有效、误到达减少或导航成功率提高。完整测试、哈希和结果见 `/home/sunrise/toponav_project/reports/corridor-evidence-design-20261015-uB3PmX/ACCEPTANCE.md`。
