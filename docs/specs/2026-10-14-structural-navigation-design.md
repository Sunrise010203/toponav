# 第三分块：结构观测最小导航闭环

已确认方案：起始节点和朝向是任务给定的定位先验，不从环境真值读取。先实现候选集合和一致性检查，不引入概率滤波或未知起点主动探索。原节点概率版源码、测试、地图和历史报告保持原样，旧版说明另存为基线文档。

## 数据边界

- 新观测仅为 `relative_open`（front/left/right/back，各为 true/false/null）和 `confidence`（0..1），不含地点类别身份、节点、坐标、边 ID 或真实朝向。null 表示方向无法判断。
- 定位输入仅为先验地图、上一轮候选 `(node_id, heading_deg)`、上一条相对动作、执行反馈和新结构观测；决策只读地图、定位结果及任务目标。禁止环境对象、真实位姿、日志进入接口。候选中的 node_id 是地图假设，不是识别标签。
- 执行反馈只含 `status`：succeeded 明确整条边执行完成，failed 明确未移动也未转向，unknown 可能执行，sent 仅已发送。模型把相对转向+走一条边作为原子动作；部分运动不建模，不能把此反馈约定冒充实车控制。
- 环境和模拟传感器可以读取真值；真值只供模拟和日志审计，不修正候选或选择动作。最终审计与控制器的 reached 状态分开。

## 候选更新

1. 初次观测从任务给定的候选开始；不是按结构类型全图认领地点。
2. succeeded：沿每个候选朝向下的相对出口预测一条已启用地图边，并更新候选朝向。
3. failed：保留原候选，不推进；完成新观测一致性检查后安全停止。
4. unknown/sent/缺反馈：预测包含原位与可能移动结果的并集，不能视为成功；即使观测排除部分候选，也停止并请求可靠反馈。
5. 用相对可通行方向检查预测集合。高置信度已知方向必须一致；低于 0.6 的观测不用于排除候选，部分方向 null 只检查已知项。
6. 空集合报告 observation_mismatch 或 transition_mismatch，不全图重定位，不挑选另一个相同路口。多个候选报告 ambiguous；观测不足报告 observation_uncertain。只有完整可信观测、唯一候选和已确认执行状态才允许继续。
7. 同结构不等于同地点：例如 N02 朝东与 N04 朝西产生相同的前/左/后开放结构，两个假设必须同时保留；依靠历史、执行反馈与后续结构排除假设。

## 执行与日志

复用原二维环境的物理通道检查，仅作为模拟执行器；新观测从物理场景及可通行状态生成。相对动作 front/left/right/back 依据真实朝向在执行器内部转换为绝对方向，不能使用定位估计来改变环境真值。

每条日志独立记录 truth（动作前/后真实状态及实际执行结果）、prior_candidates、previous_action、feedback_used、observation、localization（预测/匹配候选、估计、状态）、decision、execution_feedback。成功、失败、未知和仅发送后都再取一次观测，不因命令已发出直接推进定位。

## 验收

- 理想结构观测+可靠执行反馈完成默认路线、反向路线、封路绕行和全部可达起终点组合。
- 相同结构的不同地点/朝向保留多个候选；历史排除不可能候选，但不能按节点类型认领地点。
- 模拟 failed、unknown、sent、模糊观测、低置信度、不匹配观测有明确停止状态及候选记录。
- 故意让真实起点与任务先验不同而结构相同，控制器输入与决策不得因真值变化而改变；审计可以指出不一致，但不能干预控制器。
- 严格观测/反馈字段检查、接口和数据流测试，保证真值不通过观测/执行反馈进入定位或决策。
- 原节点概率版和原有 204 项测试继续通过，保留原源码 SHA256。新 CLI、JSON、PNG、说明和独立验收报告可复现。
