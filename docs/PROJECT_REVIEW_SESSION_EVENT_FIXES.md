# 项目检查：第七批修复——时序事件失败隔离与完成屏障

日期：2026-10-29（Asia/Shanghai）。仅修改离散原子运动协调器`simulation/navigation_session.py`的接口与状态保护；不是连续控制、真实停车、Gazebo/DDS或S2/S6验收。

## 已复现的问题

1. **异常后保留活动状态/旧票**：两张有效帧后插入畸形帧，原代码虽然抛异常，但仍保留确认窗口；调用方捕获后再送一张有效帧即可发令。非法单调时钟也有相同行为。现在先锁存`failed`、清空窗口，再传播异常，恢复好包不会继续确认。
2. **终态先解析坏包**：原`observe/feedback`在终态守卫前解析输入、验证观测，坏事件会再次抛异常。现在先做终态/超时守卫；已经`reached/failed`时不解析载荷、不读取时钟、不重新定位，只返回stop。忽略记录不再携带未验证的帧ID/反馈载荷。
3. **完成反馈半途提交**：原代码先写`completion`、清除`pending`、更新候选，再读完成墙钟；墙钟非法时会抛异常，但命令已被标成成功，转移计数却仍为0。现在先完成转移计算和时钟验证，再提交完成状态、候选、计数、阶段计时及屏障；前置失败时保留未完成命令，不把它伪装成已消费。
4. **墙钟回退降低完成屏障**：原代码直接把回拨后的墙钟写为完成屏障，恢复墙钟后可能将运动在途期间已采集的图像当成完成后新证据，发出下一条运动命令。现在记录最近一次有效墙钟，帧处理/真实完成提交若读到更小值，就锁存失败并抛`ValueError`，不更新完成屏障。墙钟相等仍允许完成，但采集证据必须严格晚于屏障。
5. **数值错误类型与有限性**：布尔/非有限/非法类型的时钟及会使有限性检查溢出的巨大整数被拒绝；巨大时长配置统一抛`ValueError`。非字符串反馈状态（包括列表）不再漏出集合成员检查的`TypeError`。时间差本身非有限也失败停止，不让它进入诊断日志。

## 异常与恢复语义

- 活动会话的畸形输入：锁存失败，预期类型/数值输入错误以`ValueError`传播。未预期的后端异常同样先锁存失败，再传播，不吞掉故障。
- 单调时钟回退/非有限时间差：返回失败stop；非法时钟值或时钟提供者异常先锁存再抛异常。终态调用不再访问提供者。
- 墙钟回退/非法值：失败并抛异常，不把采集时间改成当前时刻。`tick`仍只依赖单调时钟，坏墙钟不能延长原5秒/120秒超时。
- **格式合法但过期、未来、重复、乱序、缺视图/低置信度的观测仍可按原策略被动恢复**；不把这些普通拒绝都改成协议失败。
- 已确认成功/失败反馈及重复事件的去重规则、在途命令唯一性、公共规划/定位、三帧一致确认、0.6置信度和原次数/超时门槛不放宽。

锁存失败只保证不再发出新协调器运动命令，**不证明在途执行器已经停下**。在途命令保留为未确认诊断信息，不能当成“已物理取消”。调用方仍必须异常停车，原驱动finally和独立执行器守卫没有删除。
