# 第三十三批：独立执行器防重放历史容量上限

日期：2026-10-31。S2未通过、S6未完成，正式导航验收未恢复。

## 问题与修改

原生接收端已有4096帧上限，但Python独立执行器的`LeaseGuard.frames`仍无限追加。修改前使用实际旧类处理4097个合成合法命令，全部接受；随后使用同一修改前快照处理16385个合成合法命令，也全部接受且未锁存；这是Python集合无上限的反例，不是实际导航、物理运动或旧自然IPC压力故障的根因复现。

本批只在`simulation/gazebo_actuator.py`新增固定`MAX_ACTUATOR_FRAMES=16384`和一处耗尽拒绝分支，另增测试和文档。检查位于原包结构、期限及防重放检查之后、`MotorGate.arm/accept`和集合插入之前。满额后锁存`actuator_capacity_exceeded`及零速，拒绝新命令，不更新上一授权序号、帧、采集时间、签发时间、期限及pending-frame状态；请求序号仍沿用原协议推进，不是运动授权。

- 最后一个名额仍可正常接受原来合法的moving、observing、waiting_feedback、visual_stop或aborted命令；2200 tick的最长当前任务预算低于16384；同时兼容原有8193次零速IPC审计工作负载。原生接收端仍为4096帧，不随本上限改变。
- 满额后的所有新command证据（包括visual_stop/aborted和普通零速command）都会拒绝，**拒绝本身锁存零速**，不是拒绝安全停车。终止证据被拒绝不能当作已接受的终止/抵达证明。
- 无需新帧的STOP/shutdown走原先更早的路径，满额及已故障后仍可确认，且不重写首个故障或上一授权元数据。没有淘汰、自动清空、续租、重试或重新授权。
- 原poll先检查到期和时钟倒退；已有首故障保持。容量分支之前的原检查顺序不变。容量先于下层MotorGate验证，故满额时该原因**不能证明**命令的剩余字段都合法；下层无论是否合法均没有获得arm/accept机会。
- 审计仍按原安全原因白名单把该新原因识别为故障；严格历史/末态绑定可以完整，同时`fault_latched=true`。完整日志不等于健康运动或物理停稳。

原MotorGate只保留一个pending frame，不另有无界帧集合。16384只是本Python防重放集合的引用数上限，不是磁盘、传输、输入包解析成本或整个进程资源/执行时间上限，也不提供来源认证或硬实时安全。

## 验证范围与实际结果

新增59项测试，覆盖真实16384条边界、最长帧ID、全部command状态、首故障/期限优先、元数据不变、禁止arm/accept、STOP/shutdown，以及真实独立worker/socket/AuditPipe/审计写进程和原ACK校验/客户端失败逻辑。IPC测试明确使用合成历史填充与受控发布回调，不冒充原生物理测试。

首跑57通过、2失败：新增测试助手错误地把零授权状态对外发布的`-1.0`期限哨兵与内部`None`比较。只修正新增助手的预期，不改生产或旧测试；首跑日志/XML原样保留。修正后初版59项全部通过。

定向回归随后发现实际兼容性错误：初版4096项上限令原有8193次零速IPC测试在第4097次确定拒绝，定向1018通过、1失败，初版current为3694通过、1失败。没有把这项新回归称为旧失败；调整为固定16384项，以保留该既有工作负载，不改旧测试、原生4096上限、队列、审计超时、租约或物理门槛。新增测试也明确约束该容量关系。最终容量版本的新增测试首跑55通过、4失败，原因是新助手使用全容量统一时钟，导致1/2200条短历史已经超过其原租约；只把助手停车时刻改为各自最后签发后0.01秒，不延长任何生产租约。修正后59项通过，两个结果均保留。

初版all在结束编排时的调度竞争中已经启动；它因新报告中误用可发现的`test_*.py`快照文件名产生ImportPathMismatch收集错误，没有运行到全仓测试。原输出保留，快照改用`.py.snapshot`后缀，不增加ignore/filter。只终止精确自有编排进程（143），未向pytest发送SIGINT；实际调度状态及更正另存报告。最终策略使用全新路径重新验证，不能把初版all算成通过。

初版和修正策略各两次、共四次原生会话使用原受限左转场景、命令、图像、状态、地图与物理步进策略。诊断worker只观察真实guard调用；受控会话在第三个实际非零命令被接受后，保留5个实际帧ID并明确插入合成`diagnostic-replay-history-*`ID：初版4091个使集合达到4096，最终版16379个使集合达到16384。它没有更改已接受命令元数据/ACK或生产容量常量，**不是自然运行至帧上限耗尽**。诊断证明仅在worker退出后写盘，不在活跃租约循环做诊断I/O。
