# 场景与拓扑地图 v2 修改计划

**Goal:** 保留六节点、六边、通道关闭及合法性检查，支持不同规模/编号地图，区分拓扑、任务和几何信息，并验证相对出口对应关系。

**Architecture:** 仅迁移配置和现成工具命令，不新增导航业务源码。graph 保存拓扑、出口与可选 task；scene 保存独立允许通道清单及可选 geometry。通用 JSON Schema 负责格式，jq 负责跨节点/跨文件语义。先在暂存目录验证，再核对原文件哈希后替换目标文件。

**Tech Stack:** 已有 JSON Schema / jq / NetworkX，复用现有环境，不安装软件。

1. 备份原 configs、README、docs、reports、logs；记录哈希。复现旧 schema 拒绝 4/7 节点、其他编号、无照片/坐标字段的失败。
2. 更新通用 graph schema 并添加 scene schema；移除示例编号、数量、尺寸和逐节点坐标/类型常量，保留字段类型、唯一性、双向简单图约束及数值安全检查。
3. 迁移原六节点图、C02 关闭图、场景和 13 个错误样例：actions→exits，task 集中，N06 goal→dead_end，几何和评价信息→scene.geometry；允许无照片、无几何、无任务的拓扑加载。
4. 用相同 schema/检查命令测试原地图、4 节点任意编号、7 节点任意编号、四出口路口、重命名六节点、无几何/照片/任务地图，以及错误引用/连接/出口样例。负边长样例改为几何配置错误，不将其伪称非法拓扑。
5. 按当前节点指向来路的出口推导进入朝向；测试 N02 三种进入方向的 9 个对应、来路未知不猜测、关闭出口保留结构但不可通行。增加改变显示坐标不改变出口语义的回归。
6. 验证物理结构可达与启用边可达分离：C02 关闭仍有备选路；关闭目标通道仍是合法地图，但任务不可通行。
7. 哈希确认无并发修改，逐文件部署验证通过的配置和 README/SCENE 文档；生成新验收报告和地图哈希。原环境、图示和其余分块不变，不做 Git 提交。

## 兼容部署说明

最终检查发现已存在 simulation 程序依赖 v1 start_node/actions/length_m/position_m，直接切换默认配置会破坏旧入口；path_planning 还用显示坐标推导出口，与新约定冲突。因此 v2 完整配置和通用 schema 暂发布在 configs/v2，恢复 v1 默认配置；只改第一分块配置/文档，不改这些程序。默认程序支持 v2 的最小字段适配须用户另行确认。配置/工具验收通过不代表其他分块已支持 v2。
